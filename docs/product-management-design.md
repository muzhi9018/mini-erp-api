# 商品管理第一版设计方案

创建日期：2026-11-19。

更新日期：2026-11-21。

文档状态：后端业务已实现，包含类目、单位、商品、结构化规格、SKU、人工库存、图片、选品及内部快照服务。接口与权限见 [商品接口联调说明](product-api.md)。未对业务数据库执行建表，报价、订单及其快照读取权限入口仍按后续业务接入。

此前商品统一版本与按版本复用快照的表结构已合并到同一份完整建表脚本，包含 8 张主档表和 3 张快照表，不再单独维护增量脚本。商品版本联动和按版本获取复用快照已实现；单据接入仍待对应业务模块建设。

此前已将商品多图及完整图片快照同步到 SQL，共 11 张表。新增 `product_image`、`product_snapshot_image`，移除商品及快照主表的单主图字段，图片列表、主图及顺序统一由图片关联表保存。

2026-11-20 已交付的上一版完整 SQL 包含采购价、售价各自的 CNY / TWD 币种，以及独立 SKU 图片表，共 12 张表。

商品图片和 SKU 图片统一存入 `product_image`，通过 `image_type` 和 `owner_id` 定位归属，共 11 张商品业务表。`owner_id` 按类型保存商品 ID 或 SKU ID。SKU 无图时由前端显示商品主图。

数量小数位由 `product_sku.quantity_scale` 按 SKU 独立维护，`product_unit` 负责计量单位字典。生成快照时写入当时的 SKU 精度。

## 1. 目标与已确认范围

建立用于管理实际经营商品的独立商品档案，为后续报价单、订单提供统一的商品与 SKU 数据。

| 项目 | 第一版范围 |
| --- | --- |
| 业务结构 | 独立商品类目 → 商品 → SKU |
| 商品类目 | 独立维护，最多三级树形层级，例如装潢材料、金属衣柜 |
| 规格 | 第一版即结构化维护颜色、材质、宽度、厚度等维度和值 |
| 商品资料 | 名称、编码、类目、品牌、多张图片、简要说明、状态 |
| 商品图片 | 支持多图、排序、指定一张主图，作为商品自身图片维护 |
| SKU 图片 | 可独立设置多图，也可不填；不填时前端显示商品主图，后端只返回 SKU 自身图片 |
| 图片存储 | 商品与 SKU 图片共用 `product_image`，通过 `image_type`、`owner_id` 定位归属 |
| SKU | 独立货号、型号、规格组合、计量单位、参考价格、库存数量、状态 |
| 币种 | 仅人民币 CNY、新台币 TWD；采购价与售价分别设置币种，允许不同或相同，不提供汇率换算 |
| 国际化 | 商品业务资料只维护一套内容；系统提示、校验错误沿用英文、简体中文、繁体中文国际化机制 |
| 库存 | SKU 直接记录当前数量，允许人工录入和修改 |
| 数量小数位 | 每个 SKU 独立配置 0～6 位，同一个“米”单位可以用于整米 SKU 和允许小数的 SKU |
| 商品版本 | 每次成功更新商品及所属 SKU 数据，所属商品版本递增，同一事务原子提交 |
| 商品快照 | 按 SKU 与商品版本查找并复用，不存在时生成；快照版本对应商品版本，内容不可变 |
| 报价、订单 | 明细关联商品快照，当前商品、SKU ID 仅用于来源追溯；后续建设对应业务模块 |

本期不建设仓库、期初单、入库单、出库单、库存余额表或库存流水表；不进行自动增减、预占库存，不根据库存数量阻止报价或下单。人工将数量从 10 改为 8，只表示重新设置当前数量，不生成出库业务。

本期采用每个 SKU 一个固定计量单位，不建设多单位换算、客户专属价、阶梯价、成本核算或营销功能。类目、商品、SKU、规格、候选值和计量单位均只维护一套名称与说明，不新增语言字段、翻译表或翻译维护功能。

## 2. 与现有项目的关系

- 新增 `product` 业务模块，分别放入 `controller/product`、`service/product`、`mapper/product`、`entity/product`、`vo/product`。
- 官网继续使用既有 `website_product*` 表与接口；内部商品使用新的 `product*` 表与接口，两套类目也分别维护。
- 本期不建立官网商品与内部商品的自动同步、继承或绑定关系。
- 商品接口不设计 `locale`、`language` 等业务参数，商品名称、类目、规格、单位等业务资料不按请求语言切换。错误信息、参数校验等系统提示继续使用项目国际化机制，在 `i18n/product/messages*.properties` 维护英文、简体中文、繁体中文文案；`Accept-Language` 只影响系统提示语言。
- 复用现有用户认证、权限、附件上传、授权图片地址、`JsonResult<T>`、审计填充及逻辑删除机制。
- 图片保存附件 ID，查询时生成授权地址；实施时为现有 OSS 模块枚举补充内部商品用途，不直接复用官网商品的业务编码。
- 本文仅说明前端需要配合的页面和契约，不修改前端项目文件。

## 3. 业务模型

### 3.1 商品类目

类目用于分类和查询，不直接承担价格、库存或规格组合的身份。

```text
装潢材料
└─ 墙面材料
   └─ PVC 装饰板（商品）
      ├─ 白色 / 厚度5mm（SKU）
      └─ 白色 / 厚度8mm（SKU）

金属衣柜
└─ 两门金属衣柜（商品）
   ├─ 灰色 / 宽900mm / 深450mm / 高1800mm（SKU）
   └─ 白色 / 宽900mm / 深450mm / 高1800mm（SKU）
```

- 一个商品归属一个类目，SKU 沿用商品类目。
- 商品可以归属任意层级的有效类目，不要求只能选择末级类目。
- 顶级类目的 `parent_id` 为 0；按上级类目查询商品时，包含全部下级类目。
- 商品类目最多三级，顶级为第 1 级；新增时校验完整父级链，第 3 级类目下不能再新增子类目。
- 同一父类目下名称唯一；类目编码全局唯一。
- 类目创建后父级固定，不提供调整父级的功能。
- 类目维护按无并发场景实施，不添加显式表锁、行锁或并发协调；业务校验、分类改名与关联商品版本递增继续在事务内完成。
- 存在未删除子类目或商品时禁止删除，不自动调整关联资料的归属或删除关联资料。

### 3.2 商品

商品代表一款产品，集中维护共同资料。商品编码用于识别这一款产品，SKU 编码用于识别可以实际报价、下单的具体规格，两者分别唯一。

创建商品时同时提交规格与至少一条 SKU，在同一事务内保存。无多规格需求的商品不配置规格维度，直接创建一条默认 SKU；同一无规格商品只允许存在一条未删除 SKU。

商品名称、品牌、分类、简要说明和图片列表可以维护。商品图片支持上传多张、调整顺序和指定主图；列表为空时允许没有主图。每个 SKU 还可独立维护自己的多张图片，SKU 图片可以为空，前端按第 5.3 节规则判断是否显示商品主图，后端不回填默认图片。

停用商品后，其全部 SKU 不再出现在新增业务的选品结果中，管理详情仍然可查。

### 3.3 结构化规格

规格维度按商品定义，候选值归属于维度，SKU 选择候选值形成具体组合。例如：

| 维度 | 类型 | 候选值 | 单位 |
| --- | --- | --- | --- |
| 颜色 | TEXT | 灰色、白色 | 无 |
| 宽度 | NUMBER | 900、1200 | mm |
| 深度 | NUMBER | 450 | mm |
| 高度 | NUMBER | 1800 | mm |

- 文本和数值分字段存储，不把宽、深、高合并成一个不可筛选的字符串。
- 同一维度只能使用一种数据类型；数值维度统一使用该维度配置的单位。
- 候选值采用选择已有值、添加新值的方式维护；SKU 不提交任意文本替代规格值 ID。
- 同一商品下维度名称唯一；同一维度下候选值去重。文本去除首尾空白，数值按数值等价规则去重，例如 `900` 与 `900.0` 是同一个值。
- 一个 SKU 对每个维度必须且只能选择一个候选值，维度、候选值、SKU 必须属于同一商品。
- 同一商品下未删除 SKU 的规格组合唯一，停用 SKU 仍占用该组合。
- SKU 显示规格由维度名称、候选值和单位组合生成，显示顺序不参与 SKU 身份计算。
- 支持按候选值生成组合预览，仅提交实际经营的组合；预览不产生数据库记录，也不强制保存全部笛卡尔积。

维度结构在商品首次建立 SKU 时确定。有 SKU 后，可以增加候选值和新的 SKU；禁止直接改变维度类型、单位、增删维度或改写已被 SKU 使用的候选值。维度显示名称和排序允许修正。确需重建维度时，未被业务引用的 SKU 可显式删除后统一重建；已有业务引用时通过新商品档案承接，保留原档案供历史追溯。

### 3.4 SKU、计量单位和价格

- SKU 编码全局唯一，商品编码与 SKU 编码均不在删除后分配给其他记录。
- 每个 SKU 有一个基本计量单位，例如件、张、套、米；库存和后续单据数量使用该单位。
- 单位只定义“米、件、张”等计量含义，不设置数量小数位。每个 SKU 通过 `quantityScale` 独立配置 0～6 位，0 表示只允许整数；超出该 SKU 精度的数量直接校验失败，不静默四舍五入。
- 不为不同精度重复创建“米”单位。例如吊衣杆和法理纸共用同一个米单位，吊衣杆设置 0 位，只支持 1、2、3 米；法理纸设置 2 位，支持 1.5、1.25 米。
- 数量精度用于该 SKU 的人工库存及后续报价、订单数量，不控制采购单价、销售单价、金额或规格参数的小数位；数值规格继续按自身数值字段规则维护。
- 单位被规格或 SKU 引用后不能删除。SKU 的小数位调整不需要修改或新建单位，也不影响共用该单位的其他 SKU。
- SKU 所属商品和规格组合创建后不直接修改；计量单位仅在没有业务引用且库存为 0 时允许修正。有业务引用后，计量单位也保持不变，实物身份变化时新增 SKU。
- 参考进价即 SKU 的参考采购价，与参考售价分别维护金额和币种。两种价格均可为空，空值表示未维护，0 表示明确设置为零；金额不允许负数。
- 只支持人民币 `CNY`、新台币 `TWD`。采购价使用 `referencePurchaseCurrency`，售价使用 `referenceSaleCurrency`，可以设置为不同币种，也允许相同；不再使用一个系统统一币种代替两个价格各自的币种。
- 每个价格与其币种必须成对填写或成对为空；金额为 0 时也必须填写合法币种。清除价格时同时清除对应币种，不根据另一种价格推断，不默认补为人民币或新台币。
- 前端与数据库统一使用 `CNY`、`TWD` 编码，中文名称仅用于展示。币种复用项目已有的 `CurrencyEnum`，合法性校验集中在该枚举，必要时补充 `ofCode` 等查询方法；不重复新增币种枚举，不建设币种管理表、汇率表或自动换算功能。
- 采购价和售价分别展示金额与币种，不能跨币种直接相减计算毛利或合计；例如采购价 `100 CNY`、售价 `500 TWD` 是合法的独立设置。
- 参考价格建议统一按未税单价维护；这是设计建议，实施报价单前需要确认税价口径。参考进价不等于实际库存成本，成交价也不强制等于参考售价。

SKU 图片在统一的 `product_image` 表中按 SKU 归属保存，新增 SKU 时可不传图片或传空列表，均表示该 SKU 没有自定义图片。后续保存图片使用单独操作，不能因普通价格、库存或状态编辑而覆盖图片；详细规则见第 5.3 节。

SKU 数量小数位新增时未填写按 0 保存，编辑时未填写则保留原值，显式提交 0～6 才进行调整。调整前检查当前库存是否符合目标精度，不符合则拒绝，不自动改库存；调整成功同时递增 SKU 行版本与所属商品版本，旧快照保持原精度。

### 3.5 简单库存

`product_sku.stock_quantity` 是当前人工维护的数量，使用 `numeric(20,6)`，默认 0、非空且不得为负。

- 创建 SKU 时可填写数量，不填按 0 保存。
- 库存数量按 `product_sku.quantity_scale` 校验，不再从单位表取得精度；仅忽略无意义的末尾零，不通过舍入使不合法数量通过校验。
- 后续修改采用设置绝对数量，例如提交 15 表示保存为 15，不表示增加 15。
- 同时支持改大、改小和归零，不要求入库、出库或调整原因，不生成库存单据和流水。
- 商品详情、SKU 列表和选品结果展示该值；不同 SKU 单位可能不同，商品列表不直接合计为一个库存总数。
- 库存数量不自动变化，也不作为报价、订单是否允许提交的判断条件。
- 库存更新使用 SKU 行版本校验，过期版本保存失败，提示重新读取后确认；不默默覆盖另一人的数量修改。成功设置库存时，同时递增所属商品的统一版本。
- 普通商品资料、规格和 SKU 资料修改不写库存字段。库存通过独立操作保存，避免使用旧详情回写库存。

本期库存仅有当前值和最近修改审计信息，不提供历史库存还原、出入库追溯或库存成本报表。

### 3.6 商品快照

商品主档表示当前可维护的资料，商品快照表示某个商品版本下的一份固定 SKU 资料。快照以 SKU 为粒度，分别保存当时商品图片与该 SKU 自身图片的来源、主图和顺序，同时保存所属商品共同资料、当前选中规格和计量单位；不复制同一商品下其他 SKU 的图片。

报价、订单明细以 `product_snapshot_id` 关联快照，而不是依赖当前商品或 SKU 查询历史内容。快照中的来源商品和 SKU ID 仅供追溯，即使来源被逻辑删除，历史明细、打印和导出仍能从快照完整还原。

新建报价、直接新建订单等需要当前商品资料的场景，在保存时先按“来源 SKU ID + 当前商品版本”查找快照。有则直接复用，无则由后端生成，并与单据明细在同一事务中提交。同一版本的同一 SKU 可以被多个报价、订单共同引用，不按单据行重复生成。

快照中的 `version` 等于生成时的 `product.version`，不单独按生成次数计数。主档修改只递增商品版本，已有快照内容和版本均不修改，也不立即批量生成新快照。报价转订单继续引用报价确认的版本。详细字段见第 4 节，获取、生成和转单规则见第 9 节。

### 3.7 商品与快照版本规则

采用一款商品统一版本的方案。版本号从 0 开始，与现有 `product.version` 初始值一致；版本由服务端维护，客户端只能提交期望版本用于并发校验，不能指定新版本。

| 字段 | 含义 | 更新规则 |
| --- | --- | --- |
| `product.version` | 整款商品的统一版本，覆盖共同资料、规格和所属 SKU 数据 | 创建为 0，每次成功更新操作加 1 |
| `product_sku.version` | 单条 SKU 的行版本，继续用于资料和库存并发校验 | 创建为 0，该 SKU 被更新时加 1；不能单独用它判断快照是否过期 |
| `product_snapshot.version` | 快照对应的商品版本 | 生成时复制 `product.version`，以后不变 |
| `product_snapshot.source_sku_version` | 生成时来源 SKU 的行版本，辅助追溯 | 生成时复制，不参与快照唯一键 |

商品统一版本的递增范围包括：

- 商品名称、编码、类目、品牌、图片列表、简要说明、排序、启停或逻辑删除等资料更新；图片新增、移除、替换、排序及切换主图都属于商品更新。
- 规格维度、候选值及显示顺序的新增、修改或删除。
- 所属 SKU 的新增、资料修改、数量小数位调整、采购价或售价金额及对应币种修改、SKU 图片新增或移除及排序或切换主图、单位修正、排序、启停、库存设置或逻辑删除。
- 引用的类目名称、编码等展示资料变化，以及计量单位名称、编码等展示资料变化；同一事务中递增全部受影响商品的版本。

一次操作同时更新一款商品的多个字段或多个 SKU，只递增该商品版本一次；首次整体创建商品及 SKU 不额外累加。不同操作各自成功时分别递增，失败或回滚不递增，查询以及快照获取、生成、复用不递增。读取授权图片 URL 不属于商品数据更新；换图使用新附件并更新商品，禁止就地替换快照引用的旧文件。

所有商品及 SKU 写入入口统一执行版本规则，库存即使不进入快照内容，也按本次要求递增商品版本。任一 SKU 更新后，整款商品版本改变，其他 SKU 下一次使用时也按新商品版本查找自己的快照；不同版本即使部分内容相同，也不合并。

类目或单位等共享资料发生影响商品内容的变化时，在同一事务中修改共享资料并递增受影响商品版本，一次变更多处引用同一商品仍只加 1。类目改名需覆盖下级类目下的商品；类目维护按无并发场景实现，不增加显式锁或引用协调。单位改名需覆盖 SKU 单位及数值规格单位的引用，其锁定与引用协调随单位功能实施。

只生成被实际业务使用的版本快照，版本允许不连续。例如商品从 V0 更新到 V2，中间没有业务使用，就不补造 V1 快照；不能根据当前主档倒推不存在的历史版本内容。

## 4. 数据表设计

第一版共 11 张业务表：原有 7 张主档表加统一的 `product_image`，以及 `product_snapshot`、`product_snapshot_spec`、`product_snapshot_image` 三张不可变快照表。以下为字段和约束说明。

商品管理的 11 张表集中在 [商品管理建表脚本](sql/20261119_product_management.sql)，定义也已同步到 [完整表结构](sql/schema.sql)。

### 4.1 公共字段

各表依次包含以下公共字段，再声明业务字段：

| 字段 | PostgreSQL 类型 | 规则 |
| --- | --- | --- |

| `gmt_create` | timestamp with time zone | 默认当前时间、非空，应用自动填充 |
| `gmt_modified` | timestamp with time zone | 默认当前时间、非空，应用维护更新 |

图片统一通过 `product_image` 管理，商品表不再单独持久化 `cover_image_attachment_id`，避免主图指针与图片列表各自维护。查询返回的主图附件 ID 和 URL 从图片列表的主图记录派生，仅属于 VO 展示字段。

| `sort_order` | integer | 默认 0、非空 |

未删除记录中 `(product_id, name)` 唯一。建立商品维度排序查询索引，检查数据类型编码及文本维度不带单位的规则。

文本值和数值必须且只能填写其中一个，并由 Service 验证与维度类型一致。未删除记录中 `(spec_id, normalized_value)` 唯一，数值规范化不使用浮点运算。

### 4.6 `product_sku`：商品 SKU

| 业务字段 | 类型 | 规则 |
| --- | --- | --- |
| `product_id` | bigint | 非空，所属商品 |
| `code` | varchar(64) | 非空，全表唯一，删除后不复用 |
| `model` | varchar(128) | 选填，厂家型号等 |
| `unit_id` | bigint | 非空，基本计量单位 |
| `quantity_scale` | integer | 默认 0、非空，当前 SKU 允许的数量小数位，范围 0～6 |
| `reference_purchase_price` | numeric(20,6) | 选填，非负参考进价 |
| `reference_purchase_currency` | varchar(3) | 采购价币种，CNY / TWD，与采购价成对填写或成对为空 |
| `reference_sale_price` | numeric(20,6) | 选填，非负参考售价 |
| `reference_sale_currency` | varchar(3) | 售价币种，CNY / TWD，与售价成对填写或成对为空 |
| `stock_quantity` | numeric(20,6) | 默认 0、非空、非负 |
| `specification_key` | varchar(64) | 非空，由服务端计算的规格组合标识 |
| `status` | varchar(16) | 非空，ENABLED / DISABLED |
| `sort_order` | integer | 默认 0、非空 |
| `version` | bigint | 默认 0、非空，SKU 资料和库存操作共同使用的行版本；SKU 更新还须同时递增所属商品版本 |

编码建立全表唯一索引；未删除记录中 `(product_id, specification_key)` 唯一；建立所属商品的 SKU 查询索引。价格、数量、状态和版本设置对应检查约束。

SKU 数量小数位增加独立检查约束，限定 0～6；库存是否符合当前 SKU 精度由 Service 校验。`quantity_scale` 归属于 SKU 实体，不能在 VO 中再声明同名字段遮蔽实体属性。

采购价、售价分别增加独立检查约束：金额为空时对应币种必须为空；金额非空时对应币种必须非空，且属于 CNY / TWD。币种字段没有默认值，不能仅靠允许空值的 `IN` 检查遗漏金额与币种配对。保存价格时金额与币种作为一组更新；SKU 图片在 `product_image` 中使用 SKU 类型和对应 SKU ID 关联。

组合标识由按规格 ID 排序的“规格 ID + 候选值 ID”列表规范化后计算 SHA-256 十六进制摘要，不能使用显示名称或显示排序。无规格商品使用空列表计算的标识。标识不接收客户端传值。

### 4.7 `product_sku_spec_value`：SKU 规格关系

| 业务字段 | 类型 | 规则 |
| --- | --- | --- |
| `sku_id` | bigint | 非空，关联 SKU |
| `spec_id` | bigint | 非空，关联规格维度 |
| `spec_value_id` | bigint | 非空，关联候选值 |

未删除记录中 `(sku_id, spec_id)` 唯一，确保每个维度只选一个值。建立候选值关联查询索引以支持规格筛选。Service 在同一事务内校验维度、候选值和 SKU 的商品归属，并保证维度选择完整。

### 4.8 `product_unit`：计量单位

| 业务字段 | 类型 | 规则 |
| --- | --- | --- |
| `code` | varchar(32) | 非空，全表唯一 |
| `name` | varchar(32) | 非空，例如件、张、米、mm |
| `sort_order` | integer | 默认 0、非空 |

单位同时可供 SKU 数量和数值规格使用，只维护编码、名称、排序等字典资料，不保存数量小数位，也不提供单位之间的转换关系；名称在未删除记录中唯一。同一单位由不同 SKU 引用时，各自按 SKU 的数量小数位校验。

### 4.9 `product_image`：商品与 SKU 统一图片

| 业务字段 | 类型 | 规则 |
| --- | --- | --- |
| `image_type` | varchar(16) | 非空，PRODUCT 表示商品图片，SKU 表示 SKU 自身图片 |
| `owner_id` | bigint | 非空，PRODUCT 存商品 ID，SKU 存 SKU ID |
| `attachment_id` | bigint | 非空，关联现有图片附件 |
| `is_cover` | boolean | 默认 false、非空，是否对应商品或 SKU 自身图片组的主图 |
| `sort_order` | integer | 默认 0、非空，保存时按请求列表顺序赋值 |

图片归属使用 `ProductEnum.ImageType` 定义。数据库通过检查约束限制类型为 `PRODUCT` 或 `SKU`，Service 根据操作校验归属记录并写入对应 ID。

未删除记录中 `(image_type, owner_id, attachment_id)` 唯一，主图通过 `(image_type, owner_id)` 的部分唯一索引限制为最多一张。不同商品、不同 SKU 及数字 ID 相同的商品与 SKU 可以各自引用同一附件，各自维护主图。

建立有效记录的 `(image_type, owner_id, sort_order, id)` 排序查询索引和 `attachment_id` 引用索引。查询、替换和删除图片都同时限定图片类型和归属 ID。

两类图片均允许空列表，非空列表恰好一张主图由 Service 保证。图片移除只逻辑删除对应归属的关联，不删除附件，不创建默认商品图或占位关联。商品图片变化递增商品版本，SKU 图片变化同时递增 SKU 行版本和商品版本。

统一存储不合并业务归属：商品图片保存只修改 PRODUCT 记录，SKU 图片保存只修改该 SKU 的 SKU 记录，不得使用“按商品 ID 清空全部图片”实现商品图片列表替换。

### 4.10 `product_snapshot`：SKU 商品快照

每条记录是一份指定商品版本的完整 SKU 历史资料。同一 SKU 在同一商品版本下只保留一份，由多个业务明细共同复用。

| 业务字段 | 类型 | 规则 |
| --- | --- | --- |
| `source_product_id` | bigint | 非空，来源商品 ID，仅用于追溯，不要求历史读取时仍存在 |
| `source_sku_id` | bigint | 非空，来源 SKU ID，仅用于追溯 |
| `version` | bigint | 非空、非负，等于生成快照时的 `product.version`，服务端显式写入，无默认值 |
| `source_sku_version` | bigint | 非空，生成快照时的 SKU 行版本，非负，仅辅助追溯 |
| `product_code` | varchar(64) | 非空，当时的商品编码 |
| `sku_code` | varchar(64) | 非空，当时的 SKU 编码 |
| `product_name` | varchar(256) | 非空，当时的商品名称 |
| `brand` | varchar(128) | 选填，当时的品牌 |
| `model` | varchar(128) | 选填，当时的型号 |
| `description` | varchar(2048) | 选填，当时的商品简要说明 |
| `category_code` | varchar(64) | 非空，当时的类目编码 |
| `category_name` | varchar(128) | 非空，当时的类目名称 |
| `category_path` | text | 非空，当时的完整类目名称路径，例如装潢材料 / 墙面材料 |
| `unit_code` | varchar(32) | 非空，当时的 SKU 计量单位编码 |
| `unit_name` | varchar(32) | 非空，当时的 SKU 计量单位名称 |
| `quantity_scale` | integer | 非空，从当时的 SKU 复制的数量精度，0～6，不再从单位表读取 |
| `specification_text` | text | 非空，当时按显示顺序生成的规格摘要，无规格时为空字符串 |

快照 ID 使用独立主键；建立全表唯一索引 `uk_product_snapshot_sku_version (source_sku_id, version)`，数据库保证同一 SKU、同一商品版本只有一份快照。来源 SKU ID 已全局唯一，不额外按单据、业务类型、创建人或 SKU 行版本拆分唯一性。

建立 `(source_product_id, version, id)` 普通索引用于查询整款商品某版本的 SKU 快照。数量精度和版本设置对应检查约束，逻辑删除标记限制为 false。`version` 直接表示来源商品版本，不再重复声明 `source_product_version`，也不作为可递增的快照行版本使用。

快照主表不单独保存 `cover_image_attachment_id`。当时的商品图片与 SKU 自身图片均保存在 `product_snapshot_image`，使用明确来源区分，不把商品主图复制成 SKU 自定义图片。历史展示只读取快照，不回查当前商品或 SKU 图片。

不保存当前库存、参考采购价或采购币种。数量、实际成交单价、交易币种、税费和金额属于单据交易信息，由报价、订单独立冻结；当前参考售价及其币种只提供初始建议，不是历史交易价格或币种的读取来源。

### 4.11 `product_snapshot_spec`：快照规格明细

| 业务字段 | 类型 | 规则 |
| --- | --- | --- |
| `snapshot_id` | bigint | 非空，所属商品快照 |
| `source_spec_id` | bigint | 非空，来源维度 ID，仅用于追溯 |
| `source_spec_value_id` | bigint | 非空，来源候选值 ID，仅用于追溯 |
| `spec_name` | varchar(64) | 非空，当时的维度名称 |
| `value_type` | varchar(16) | 非空，TEXT / NUMBER |
| `text_value` | varchar(128) | 当时选中的文本值 |
| `number_value` | numeric(20,6) | 当时选中的数值 |
| `unit_code` | varchar(32) | 数值规格的单位编码，无单位时为空 |
| `unit_name` | varchar(32) | 数值规格的单位名称，与编码同时有值或同时为空 |
| `sort_order` | integer | 非空，当时的显示顺序 |

同一快照内 `(snapshot_id, source_spec_id)` 全表唯一，建立 `(snapshot_id, sort_order, id)` 排序查询索引。检查值类型、文本值与数值二选一、值与类型一致、文本维度无单位以及单位编码名称成对填写，逻辑删除标记限制为 false。快照生成时一次性复制规格名称、选中值及单位，不通过来源 ID 动态获取显示内容；无规格 SKU 对应 0 条规格明细。

### 4.12 `product_snapshot_image`：快照图片明细

| 业务字段 | 类型 | 规则 |
| --- | --- | --- |
| `snapshot_id` | bigint | 非空，所属商品快照 |
| `image_source` | varchar(16) | 非空，PRODUCT 表示商品图片，SKU 表示该 SKU 自身图片 |
| `source_image_id` | bigint | 非空，统一来源表 `product_image.id`，仅用于追溯 |
| `attachment_id` | bigint | 非空，当时使用的图片附件 |
| `is_cover` | boolean | 非空，当时是否主图 |
| `sort_order` | integer | 非空，当时完整图片列表的显示顺序 |

生成快照时，从同一张 `product_image` 表分别读取该商品的 PRODUCT 记录，以及当前 SKU 的 SKU 记录，按各组当时顺序复制全部有效图片。来源记录的 `image_type` 复制为快照 `image_source`，共用同一个图片类型枚举；保留各组主图和顺序，不复制其他 SKU 图片。SKU 无图时不生成 SKU 来源记录，但保留 PRODUCT 来源供前端判断；两组都为空时对应 0 条图片快照记录。

建立 `(snapshot_id, image_source, attachment_id)` 全表唯一索引，允许同一附件在商品来源和 SKU 来源分别出现；主图部分唯一索引改为 `(snapshot_id, image_source)` 且 `is_cover = true`，每个非空来源组恰好一张主图。排序查询索引改为 `(snapshot_id, image_source, sort_order, id)`，保留 `attachment_id` 引用查询索引；检查来源枚举及 `is_deleted = false`。

读取时返回带 `imageSource` 标记的明确类型图片列表，后端不将 PRODUCT 记录改成 SKU 记录，也不生成“最终生效图片”列表。前端有 SKU 来源图片时显示该组；没有时只显示同一快照中 PRODUCT 来源的主图，不能改用当前商品主图或把整组商品图片当作 SKU 自身图片。

来源图片关联被删除后仍保留本表记录。图片快照不单独递增版本，其内容归属于 `product_snapshot.version`，与快照主表及规格明细一起新增、复用和保留，不提供编辑或删除入口。

### 4.13 建表脚本与实现边界

- `20261119_product_management.sql` 包含 11 张商品业务表，使用事务提交建表、索引、约束和注释。使用 `schema.sql` 初始化全库时会创建同样的商品表定义，两种建表方式二选一。
- 完整建表脚本要求目标表尚不存在，不用于覆盖或重建已有商品表，不自动回填历史快照；不再单独提供快照增量脚本。
- 类目、商品、SKU、单位编码使用全表唯一索引；类目同父级名称、单位名称、维度名称、规范化候选值、SKU 规格组合和 SKU 维度选择使用有效记录部分唯一索引。停用不会释放编码或规格组合。
- 查询索引覆盖类目树、商品与 SKU 排序、单位引用、候选值排序、数值规格区间、候选值反查 SKU，以及当前和快照图片的排序、附件引用。排序查询均可使用 ID 作为同序号下的稳定顺序。
- 状态和值类型要求显式写入；规格组合标识统一保存 64 位小写十六进制摘要，不设置默认值。`normalized_value` 与组合标识由服务端生成，数据库不根据名称、排序或客户端输入代算。
- 数据库检查约束覆盖类目直接自引用、SKU 数量小数位、状态、值类型、文本维度不带单位、候选值二选一、价格和库存非负、版本非负及摘要格式。类目深层环路、跨表归属、完整规格选择、引用删除限制及数量是否符合 SKU 精度仍由业务事务校验，不增加物理外键或触发器。
- `numeric(20,6)` 最多容纳 14 位整数、6 位小数；数据库可能对超出小数位数的值自动舍入，Controller 必须在入库前拒绝超出精度的输入。币种目标规则按第 3.4 节限定为 CNY / TWD，税价口径仍需在报价业务中明确。
- 快照按 `(source_sku_id, version)`、规格明细按 `(snapshot_id, source_spec_id)`、图片明细按 `(snapshot_id, image_source, attachment_id)` 建立全表唯一索引，不使用逻辑删除条件释放唯一键；三张快照表均通过检查约束禁止将 `is_deleted` 设置为 true。版本非负、数量精度、规格值类型一致性和单位成对填写由数据库约束保护。
- 快照指向商品、SKU、维度、候选值及图片关联的来源 ID 不设置存在性依赖，不使用主档级联删除。快照与其规格、图片明细作为同一业务事务整体新增，只有完整快照才能被单据引用。
- 现有 `product.version` 字段承载统一商品版本，商品与 SKU 版本的 SQL 注释已同步。版本联动、加锁后获取或创建快照、只新增和读取的操作限制仍需在 Service 中实现；检查约束不替代完整的快照不可变规则，不通过触发器自动更新版本或生成快照。
- 统一图片表按第 4.9 节校验图片类型，按 `(image_type, owner_id)` 限定附件重复和主图唯一性。快照图片保留来源维度，非空图片组恰好一张主图、连续排序及完整复制由 Service 事务保证。
- 商品及快照主表不保留 `cover_image_attachment_id`，旧快照主图附件索引已移除。所有商品表结构统一维护在完整脚本中，不单独提供图片增量 SQL。
- 两组价格币种配对约束分别校验采购价和售价，显式检查非空币种及 CNY / TWD 白名单，避免 PostgreSQL 的空值检查语义放过半组数据；币种与图片来源字段均无默认值。
- 本次按重建表结构交付，直接维护 `CREATE TABLE`、索引及检查约束定义，不添加迁移或业务表删除语句，不自动补币种或推断历史图片来源。

建表 SQL 已移除单位表的 `quantity_scale` 及对应约束，在 SKU 表增加默认值为 `0`、范围为 0～6 的非空字段。快照表保留原字段，生成时由后端复制来源 SKU 的精度。若需承接旧数据，应将原单位精度复制到各自对应的 SKU，并保留既有快照中的精度。

## 5. 核心业务规则

### 5.1 创建与编辑

1. 新增时原子保存商品、商品图片、规格维度、候选值、SKU、SKU 可选图片及规格关系，任何一步失败全部回滚。
2. 普通编辑按允许字段写入，不覆盖主键、审计信息、逻辑删除标识、组合标识或库存数量。
3. 所有商品或所属 SKU 更新均按第 3.7 节递增 `product.version`，更新与版本递增同一事务提交。SKU 资料、状态和库存更新还要校验并递增 SKU 行版本，成功后返回对应的新版本。
4. 商品更新、SKU 更新和快照获取统一先锁商品、再按需锁 SKU；涉及多款商品、多个 SKU 时各自按 ID 升序处理。共享资料变更在同一事务中更新资料和受影响商品版本，类目维护不增加显式锁；禁止通过普通 Mapper 写入绕过版本递增。
5. 数量、价格、数值规格使用 `BigDecimal`，写入前校验范围与精度，不能依赖数据库截断或舍入。
6. 商品快照只新增和读取。主档资料、规格显示名称、参考价格或库存修改，不更新已经生成的快照。

### 5.2 启停与删除

- 商品和 SKU 均使用 ENABLED / DISABLED。选品必须同时满足商品启用、SKU 启用及各自未删除。
- 停用商品不批量改写各 SKU 原有状态；重新启用商品后，原先单独停用的 SKU 仍保持停用。
- 库存数量为 0 的 SKU 允许按规则逻辑删除；有库存时先明确将数量设置为 0，再执行删除。报价、订单已持有独立快照，不因历史快照存在而阻止来源 SKU 的逻辑删除。
- 商品删除前逐条检查所属 SKU，全部满足删除条件后，在同一事务内逻辑删除商品及统一图片表中该商品的全部归属记录、规格、候选值、SKU、规格关系；单独删除 SKU 时，只删除统一图片表中该 SKU 的 SKU 类型记录，不影响商品图片或其他 SKU 图片。
- 候选值、维度和单位存在有效主档引用时不能单独删除，不能因删除字典资料造成当前规格悬空；快照已经复制所需值，其来源 ID 不构成对主档的存续依赖。
- 删除商品、SKU、图片关联或规格资料时，绝不删除、清空或重写相关快照及其图片、规格明细；历史单据始终按快照读取。快照本身不提供逻辑删除、物理删除或随单据删除的级联清理能力。

### 5.3 图片与业务数据

商品维护可选的多张图片和简要文字。图片列表允许为空；非空时恰好有一张主图，商品列表和商品详情使用同一套主图规则，不额外维护另一个主图指针。SKU 与选品的图片返回和前端回退规则见本节后半部分。

- 保存图片时提交完整目标列表，列表项包含附件 ID 和主图标记，列表顺序就是展示顺序。同一附件不能在同一商品列表重复出现，不能传入多张主图。
- 未显式指定主图时，服务端选择目标列表第一张作为主图。因此移除原主图但仍有图片时，由剩余第一张补位；清空列表后主图为空。
- 新增、移除、替换、排序及切换主图均在锁定商品后，于同一事务保存完整列表并递增商品版本一次。切换主图时先解除旧主图标记，再设置新主图，避免触发部分唯一索引冲突。
- 附件需存在、未逻辑删除且属于允许的图片类型。仅上传文件尚未绑定商品时，不修改商品版本；保存图片关联后才构成商品更新。
- 图片关联按附件 ID 识别并复用已有有效记录，移除的关联逻辑删除。删除图片关联或商品不直接删除附件记录和实际对象，快照引用的旧图片继续保留。
- 查询按 `sort_order`、ID 返回明确类型的图片列表，批量生成授权地址。URL 仅是查询结果，不作为业务持久化字段；空列表返回 `[]`，派生主图附件 ID 和 URL 返回空值。

图片资料由专用保存接口更新，普通商品资料编辑不覆盖图片列表。创建商品时图片列表与其他资料一起原子保存，初始商品版本仍为 0。

商品和 SKU 图片共用 `product_image`，但归属和列表操作分别处理。SKU 图片沿用上述附件校验、排序、主图与关联保留规则，另有以下边界：

- 新增 SKU 的 `images` 可省略、传 null 或 `[]`，均表示没有自定义图片。保存已有 SKU 图片时，`images` 必须明确提供，可用 `[]` 清空；缺失或 null 不视为清空。普通 SKU 编辑、库存或启停接口不更新图片。
- SKU 图片新增、移除、替换、排序及主图切换使用 SKU 行版本校验，同一事务递增该 SKU 行版本与所属商品统一版本各一次。修改商品图片不改写 SKU 自定义图片。
- SKU 详情、管理列表和选品接口只返回该 SKU 自身的图片及授权地址；没有图片时固定返回 `images: []`，不将商品主图或商品图片列表填入，不额外返回后端拼装的默认图或生效图。
- 前端自行判断：有 SKU 自身图片则显示其图片；没有则显示该商品的一张主图。商品主图从已有商品详情、列表或前端已加载的数据中取得，后端不为 SKU 查询额外拼装商品主图；商品也没有主图时由前端显示占位状态。
- 不能为实现回退而给每个无图 SKU 批量插入商品主图关联。历史单据按快照中保留的两种图片来源执行相同前端判断，不回查当前主图。
- 保存接口根据路由及已校验的商品或 SKU 设置 `image_type` 和 `owner_id`。客户端图片条目只提交可编辑字段。按附件 ID 复用和移除记录时，同时限定图片类型与归属 ID。

## 6. 接口方案

商品、图片、规格及 SKU 接口集中到 `ProductController`，类目、计量单位分别使用对应 Controller。SKU 币种、SKU 图片及选品图片已更新，接口契约见 [商品接口联调说明](product-api.md)。快照 HTTP 读取入口随关联单据权限接入。

### 6.1 接口分组

| 方法与路径 | 用途 |
| --- | --- |
| `GET /product/category/tree` | 查询类目树 |
| `POST /product/category/create` | 新增类目 |
| `POST /product/category/update` | 修改名称、排序、备注 |
| `POST /product/category/delete` | 删除空类目 |
| `GET /product/unit/list` | 查询计量单位 |
| `POST /product/unit/create` | 新增单位 |
| `POST /product/unit/update` | 修改单位资料，遵循引用限制 |
| `POST /product/unit/delete` | 删除未引用单位 |
| `GET /product/list` | 分页查询商品 |
| `GET /product/detail` | 查询商品、规格和 SKU 完整详情 |
| `POST /product/create` | 一次创建完整商品档案 |
| `POST /product/update` | 修改商品共同资料 |
| `POST /product/images/save` | 保存完整图片列表，支持新增、移除、排序、指定主图，并递增商品版本 |

| `POST /product/delete` | 删除符合条件的商品及其附属资料 |
| `POST /product/spec/create` | 添加维度及候选值，仅允许未建立 SKU 的商品 |
| `POST /product/spec/update` | 修改维度显示名称、排序 |
| `POST /product/spec/delete` | 删除没有 SKU 引用的维度 |
| `POST /product/spec/value/create` | 新增候选值 |
| `POST /product/spec/value/update` | 修改未被 SKU 使用的候选值，或仅修改排序 |
| `POST /product/spec/value/delete` | 删除未被 SKU 使用的候选值 |
| `GET /product/sku/list` | 分页查询 SKU，展示库存和规格 |
| `GET /product/sku/options` | 分页选品，仅返回有效 SKU |

| `POST /product/sku/preview` | 只读组合预览，单次最多 1000 个组合 |
| `POST /product/sku/create` | 批量创建商品下的实际规格组合 |
| `POST /product/sku/update` | 修改 SKU 允许编辑的资料，不写库存 |
| `POST /product/sku/images/save` | 保存 SKU 自身完整图片列表，可清空，递增 SKU 与商品版本 |
| `POST /product/sku/change-status` | 修改 SKU 启停状态 |
| `POST /product/sku/stock/set` | 设置 SKU 当前库存绝对数量 |

### 6.2 请求、响应与查询

- 全部返回 `JsonResult<T>`，分页返回 `JsonResult<IPage<对应VO>>`；页码和每页数量只使用 `pageNum`、`pageSize`。
- 对应实体、VO 或 record 明确声明字段，嵌套规格、值、SKU 和筛选条件均使用有明确类型的列表；不使用 `Map`、`JSONObject`、`Object` 或原始泛型承载接口结构。
- 优先让 VO 继承对应实体，只增加类目名称、图片列表、图片 URL、规格列表等字段，不重复声明实体字段。请求中的继承字段不代表允许全部写入，Service 仍使用写入白名单。
- 创建商品支持明确类型的 `images` 列表；图片保存请求固定包含 `productId`、`expectedVersion`、`images`，期望版本指商品版本，列表项只允许写入 `attachmentId`、`isCover`。`images` 必填，可传 `[]` 明确清空，不能将缺失字段或 null 当作清空；图片顺序按列表顺序保存，成功返回图片列表及新商品版本。
- 商品详情通过 `List<ProductImageVO>` 返回商品图片，VO 继承对应图片实体，仅增加授权 URL 等展示字段；商品列表可返回由商品主图记录派生的 `coverImageAttachmentId`、`coverImageUrl`，这些字段不接受独立写入，也不作为 SKU 接口的默认图片回填。
- 商品与 SKU 图片统一复用 `ProductImage`、`ProductImageVO`，不新增 SKU 图片实体或图片 VO。`ProductSkuVO` 增加 `List<ProductImageVO> images`；SKU 图片保存复用该 SKU 模型，校验 `id`（SKU ID）、`expectedVersion`（SKU 行版本）、`images`，列表项只允许写入 `attachmentId`、`isCover`。图片归属由 Service 设置，顺序按列表保存；成功返回 SKU 自身图片及新 SKU、商品版本。
- SKU 新增与修改增加 `referencePurchaseCurrency`、`referenceSaleCurrency`，分别与原价格字段成组校验、写入、清除。管理详情同时返回两组金额和币种；选品只返回参考售价及其币种，不返回参考采购价或采购币种。
- SKU 数量小数位复用现有新增、编辑接口及 `ProductSkuVO`，字段名为 `quantityScale`；单位维护不再接收或返回该字段。将属性移入 `ProductSku` 实体后，移除 `ProductSkuVO` 中原有同名展示属性，由继承取得，避免字段遮蔽；SKU 详情、选品和快照中的 `quantityScale` 都从 SKU 取值，不通过单位关联计算。
- 创建完整商品时，尚未生成 ID 的维度和值通过本次请求内唯一的 `clientKey` 关联。新增规格 VO、候选值 VO 分别携带该字段，SKU 中的选择项明确包含 `specClientKey`、`valueClientKey`；服务端校验引用完整后生成 ID。临时键仅用于本次创建，不入库，不作为后续业务 ID。
- 既有商品新增 SKU 与完整商品创建共用 `ProductSkuVO`。前者通过 `specValues` 提交 `specId`、`specValueId`，后者通过 `selections` 提交本次创建的临时键。
- 库存设置请求固定包含 `skuId`、`stockQuantity`、`expectedVersion`，其中期望版本明确指 SKU 行版本；返回 `skuId`、已保存数量、新 SKU 行版本和新商品版本。相同旧版本的重试不再次覆盖最新值，响应丢失时通过查询确认当前状态。
- 商品列表支持关键字、类目及后代、状态筛选；关键字覆盖商品名称、商品编码、SKU 编码和型号。经 SKU 匹配的商品按商品 ID 去重后分页，避免联表导致重复行或总数错误。
- SKU 查询和选品增加商品、类目、状态、规格条件。数值规格可按同一维度的数值区间筛选，数值范围单位与该维度一致；文本规格按候选值筛选。同一次查询的多个规格条件使用“全部满足”语义。
- 类目、规格、候选值、SKU 使用 `sort_order`，相同排序值再按 ID 排序，确保分页稳定。
- 选品结果返回 SKU ID、商品名称、货号、型号、结构化规格、单位、参考售价及 `referenceSaleCurrency`、当前库存、SKU 自身 `images`、`productVersion` 和 `skuVersion`，不带采购价格、采购币种或管理审计字段。移除现有选品结果中从商品主图取得的回退逻辑，不通过 `coverImageAttachmentId`、`coverImageUrl` 给无图 SKU 回填商品主图。
- 历史商品使用独立的 `ProductSnapshotVO`，继承快照实体并增加明确类型的 `List<ProductSnapshotSpec>` 和 `List<ProductSnapshotImageVO>`；图片 VO 继承快照图片实体并增加授权 URL。不通过当前商品 VO 或当前图片列表临时拼装历史快照。
- 报价、订单 Service 在保存明细的事务内调用商品快照服务按当前版本获取或创建快照，返回已有或新建的同一种快照结果；不提供客户端独立创建、更新、删除快照的通用 HTTP 接口，也不接受客户端伪造名称、规格或版本等快照内容。

SKU 维护的新增字段示例：参考采购价 `100` 配 `referencePurchaseCurrency=CNY`，参考售价 `500` 配 `referenceSaleCurrency=TWD`；`images: []` 表示该 SKU 未配置图片，并不表示没有可在前端显示的商品主图。后端不换算金额，也不改写空图片列表。

## 7. 校验、事务与权限

### 7.1 校验位置

Controller 处理不依赖数据库的校验：请求与字段非空、长度、数值范围、精度、合法枚举编码、价格与币种配对、重复图片、多主图、列表内部结构及字段关系。先判空再遍历；分页提示复用现有公共校验提示。

Service 处理数据库相关校验：编码重复、类目存在与环路、单位引用、规格归属、候选值重复、组合冲突、行版本、记录状态与删除条件。多表写入使用 `@Transactional(rollbackFor = Exception.class)`，不能只在事务外预检查。

获取或创建快照与单据保存必须共享同一事务。按第 9.2 节先锁商品，再读取当前版本并查询快照；所有相关资料更新同样先锁商品，保证“版本号、商品资料、图片列表、规格和字典显示内容”对应同一状态。可在 PostgreSQL READ COMMITTED 下按此锁定顺序读取，不把多次无锁查询拼装成快照。共享资料修改必须同步递增受影响商品版本；类目维护按无并发场景实施，不额外增加显式锁。

商品资料在选品后变化时，按选品返回的 `productVersion`、`skuVersion` 提示重新确认，不静默使用其他版本。遇到死锁或序列化等要求事务回滚的冲突时，回滚并重试整个保存事务，再重新校验期望版本，不能在已经失败的事务中继续补查和写入。

数据库对编码、规范化候选值、规格组合和 `(source_sku_id, version)` 快照键进行唯一约束保护。业务预检查用于友好提示，编码或规格重复等冲突转换为项目业务异常；快照创建竞争按第 9.2 节重试并复用已有记录。版本校验以带期望版本的原子更新是否命中为准。

### 7.2 枚举、提示与转换

- 商品同域枚举集中定义在 `enums/ProductEnum.java`，保留 Status、SpecValueType，并增加 ImageType（PRODUCT / SKU），同时用于统一图片表归属和快照图片来源，不重复定义相同取值的来源枚举。币种复用已有独立枚举 `CurrencyEnum`（CNY / TWD），按需补充编码合法性检查方法；不使用序号持久化，不把未知币种静默转成正常值。
- 沿用项目 `Assert` 的“条件命中即抛异常”语义和 `BusinessException`，使用稳定的业务提示 key、中文兜底文案及独立占位参数。
- 商品业务资料不做多语言，不影响系统层面的提示国际化。商品专属系统提示同步维护 `i18n/product/messages.properties`、`messages_zh_CN.properties`、`messages_zh_TW.properties` 并注册消息源，按请求 `Accept-Language` 选择文案；Java 中的中文仅作为缺失资源时的兜底，分页等公共提示继续复用公共资源。
- 对象转换使用 `BeanConvertUtils` 与 MapStruct Plus 配置，转换后显式处理主键、关联 ID、审计字段、状态、库存、版本和组合标识。
- 异常响应沿用当前项目处理方式；本方案不要求修改全局异常协议，也不把业务错误承诺为尚未实现的 HTTP 状态码。

### 7.3 权限

接入现有角色权限体系，对类目维护、单位维护、商品查询、新增、编辑、启停、删除和库存设置分别检查权限。库存设置仅更新库存与版本，不借助普通资料编辑接口绕过权限。

参考采购价及采购币种属于内部管理信息，管理接口按相应权限返回；选品模型不包含这两个字段。新增业务的选品接口需登录授权，不作为官网公开接口开放。

快照读取权限来自引用它的报价、订单等业务单据。知道快照 ID 不代表可以读取，接口不能只凭普通商品查询权限开放全部历史快照；引用它的单据仍可访问时，来源商品停用或删除不阻止快照读取。同一快照可被多张单据引用，创建人不是快照的独占所有者；按用户有权读取的关联单据校验权限。

## 8. 前端配合范围

本节定义商品管理的前端实施规则。前端实现位于 `mini-erp-web`，本后端仓库维护设计方案和接口约定。

| 页面或区域 | 主要内容 |
| --- | --- |
| 商品类目 | 树形查询、新增、改名、排序、删除 |
| 计量单位 | 单位名称、编码、排序维护，不设置数量小数位 |
| 商品列表 | 主图、编码、名称、类目、SKU 数、状态、更新时间及筛选 |
| 新增商品 | 共同资料、多图上传、主图指定、拖动排序、规格维度。多规格商品先勾选组合，再展开行内编辑或按规格分组批量填充 SKU，最终一次保存已加入的 SKU |
| 商品详情 / 编辑 | 图片列表与主图展示，支持增删图片和排序；按规则编辑资料、增加候选值和 SKU |
| SKU 列表 | 货号、型号、规格、单位、数量小数位、两组参考金额及各自币种、SKU 自身图片、当前库存及状态 |
| SKU 图片维护 | 可选多图上传、主图指定、排序与清空；无图时由前端显示商品主图 |
| 库存设置 | 读取最新数量及版本，填写目标数量后独立保存；冲突时重新读取并提示用户确认 |
| 后续选品 | 按 SKU 展示，支持货号、名称、类目和结构化规格筛选 |
| 后续单据商品详情 | 按 `productSnapshotId` 展示当时资料及完整图片列表；当前商品删图或删除后仍可预览、打印和导出 |

普通资料编辑表单不携带库存写入语义。当前库存按 SKU 单位展示；规格未结构化完成或组合重复时，前端提示具体维度，但后端仍执行完整校验。商品模块页面不提供语言选择、翻译维护或按语言分别编辑资料的入口。

价格表单分别提供采购价币种和售价币种选择，选项只有人民币 CNY、新台币 TWD，不能只设置一项公共币种。SKU 展示和选品组件自行处理图片回退，不把商品主图作为 SKU 自定义图片提交给后端；后端不会新增填充默认图片的数据组装流程。

SKU 编辑表单单独设置数量小数位；选择相同单位的其他 SKU 不跟随修改。数量输入控件按该 SKU 的 `quantityScale` 限制输入，历史单据则使用绑定快照中的数量精度；前端校验不替代后端校验。

### 8.1 新增商品的规格组合选择与 SKU 填写

#### 8.1.1 选择和调整规格组合

- 多规格商品依次完成「基本资料与图片」「设置规格」「选择组合」「填写 SKU」。设置规格后生成候选组合，在「选择组合」步骤至少勾选一组才能继续。无规格商品直接进入默认 SKU 填写。
- 「填写 SKU」只展示已加入的规格组合。每行显示规格组合和 SKU 摘要，整行作为展开或收起入口。展开后在行内编辑货号、型号、计量单位、数量小数位、初始库存、两组参考价格及币种、状态、排序和 SKU 图片。填写内容写入当前草稿，收起时保留并更新摘要。勾选操作集中在「选择组合」步骤和「调整规格组合」弹窗，填写页的列表工具栏只提供「调整规格组合」和「批量填充数据」。
- 「调整规格组合」弹窗列出已生成的全部组合，打开时回显当前勾选状态。确认后，新勾选的组合加入填写页，取消勾选的组合从填写页移除。取消或关闭弹窗时保留打开前的选择。全部移除时显示空状态，禁用批量填充和保存商品，可重新打开弹窗加入组合。
- 同一新增商品草稿内，按规格维度、候选值的临时键识别组合。返回上一步时保留仍有效的选择和录入内容。已移除的组合若在同一草稿内重新勾选，恢复原来填写的数据。

#### 8.1.2 按规格分组批量填充 SKU

**选组与匹配。** 「批量填充数据」弹窗展示当前规格维度和候选值，每个维度可以选一个值或留空。匹配范围为填写页已加入的 SKU，所选维度必须全部匹配，留空维度匹配其全部候选值。使用规格维度、候选值的临时键判断匹配，弹窗中的选择顺序和规格展示名称不影响匹配。全部维度留空时匹配「全部已添加 SKU」，预览显示命中数量。

| 选择条件 | 匹配结果 |
| --- | --- |
| 宽度 100、高度 600，颜色留空 | 该规格有 10 种颜色，若其中 4 种已加入，则只命中这 4 行 |
| 先选高度 600，再选宽度 100 | 对同一批已加入的 SKU，命中行和逐行编号保持一致 |
| 高度 600、颜色红色，宽度留空 | 若宽度 100、200、300 的红色组合均已加入，则命中这 3 行 |

**填写与覆盖。** 可填 SKU 编码前缀、型号前缀及需要共用的 SKU 资料，包括单位、数量小数位、初始库存、参考采购价和币种、参考售价和币种、状态、排序及可选 SKU 图片。复用现有字段和校验规则。字段未指定时保留各行原值，显式输入的 `0` 按有效值填充。金额与对应币种作为一组填写，批量未填写的价格组或图片保留原值。应用前展示命中数量和将覆盖的字段，涉及已填值时提示覆盖。多次填充允许分组交叉，后一次确认只覆盖交集行中本次指定的字段。

**稳定编号。** 对命中行沿用组合生成时的维度顺序和各维度候选值顺序。在命中范围相同的情况下，弹窗中的点击顺序、页面筛选、分页和填写的 SKU 排序值均不影响编号。SKU 编码和型号各自接受前缀，共用同一行序号。每次应用从 1 开始，后缀至少两位，超过 99 后自然递增。例如命中 4 行，填写前缀 `SKU-B` 和 `M-B` 时，分别生成 `SKU-B-01` 至 `SKU-B-04` 和 `M-B-01` 至 `M-B-04`。未填写某个前缀时保留该字段，应用后可在行内修正。

**预览与应用。** 确认前预览命中行及编号。前端按合并后的值校验编码与型号长度、数量小数位与库存兼容性、金额币种配对等规则，其中编码最长 64，型号最长 128。在所有已加入的 SKU 中检查编码冲突，包括已加入但未命中本次分组的行，并标出冲突对象。无匹配、校验失败或取消时保留草稿原样。成功应用只更新命中行的指定字段，已加入的组合范围由「调整规格组合」维护。

**保存商品。** 通过现有 `POST /product/create` 一次提交，`skus` 仅包含当前已加入的 SKU，每条 SKU 按现有协议通过 `selections` 引用对应的规格和候选值临时键。全局 SKU 编码唯一性继续由现有接口校验。组合选择、行内编辑与批量填充都在前端草稿完成，沿用现有后端接口和数据库结构。

#### 8.2.3 布局与交付检查

- 以业务内容容器为对齐基准，使用 V8 的列比例和换行方式适配现有应用布局。SKU 展开区在业务内容宽度不超过 `800` 时改为单列，批量填充弹窗在视口宽度不超过 `820` 时改为上下布局。桌面大屏按原型直接显示操作入口，所有可交互状态保持可访问。

## 9. 商品快照与报价、订单接入契约

### 9.1 关联结构

本期明确快照模型和接入契约，不创建报价单、订单表和对应业务接口。后续明细的核心关联为：

```text
报价明细 ── product_snapshot_id ── 商品快照 ── 快照规格明细 / 快照图片明细
订单明细 ── product_snapshot_id ── 商品快照 ── 快照规格明细 / 快照图片明细
```

报价、订单的每条商品明细必须持有非空 `product_snapshot_id`，关联一份已经完整保存的快照。明细可以额外保留来源 SKU ID 方便统计，但历史商品信息的读取入口始终是快照 ID，不能在快照缺失时回退当前主档拼装历史内容。

商品、SKU、类目、单位和规格的来源 ID 都是追溯信息；名称、编码、规格值、计量单位等历史显示字段直接取自快照，不要求来源记录存在或处于启用状态。

### 9.2 按版本获取或创建快照

新建报价明细、直接新建订单明细或草稿明确刷新商品资料时，由后端执行以下流程：

1. 开启单据保存事务，按来源商品 ID 锁定商品行，再按需锁定对应 SKU；校验来源归属、未删除和启用状态，以及选品提交的期望版本。
2. 在锁定后读取最新 `product.version`，组成唯一查找条件 `(source_sku_id, version)`。不能使用客户端版本替代当前版本，也不能只使用 SKU 行版本查找。
3. 如果对应快照已经存在，直接取其快照 ID，不重建规格或图片明细、不更改创建时间或创建人。
4. 如果不存在，读取该版本的商品、商品图片、当前 SKU 自身图片、类目路径、规格和值、单位等资料，先保存快照主记录，再按 PRODUCT、SKU 来源写入完整图片明细并保存规格明细。快照 `version` 写入刚读取的商品版本，图片保留各自主图和顺序，所有记录同一事务保存，完整成功后才能被单据引用；无 SKU 图片时不生成伪造的默认 SKU 图片。
5. 单据明细保存获取到的 `product_snapshot_id` 及本单据的交易字段，再整体提交。任意步骤失败，新单据数据和本事务新建的快照全部回滚；事务外已存在、已被其他单据使用的快照保持不变。

商品更新也必须先锁同一商品行，再修改数据和递增版本。因此同一版本的并发使用会串行执行“查询、必要时生成”：先完成的事务创建快照，后续事务查询并复用同一快照 ID。唯一索引 `uk_product_snapshot_sku_version` 是最终数据库保护，不能仅依赖“先查后插”的应用判断；出现需要回滚的竞争冲突时，重试整个事务后读取已有快照，不能插入第二份或覆盖旧快照。

同一商品版本下的不同 SKU 分别保存各自快照。同一 SKU、同一商品版本可以跨报价、订单和同一单据的多行复用，数量和成交价格不同不影响快照复用；无需按商品内容计算另一套去重哈希。

浏览商品、搜索、选品、快照读取不生成新版本，不创建无需求的快照；商品更新仅递增版本，等下一次业务实际使用时再获取或创建。过去版本已有快照可以通过快照 ID 读取，过去版本没有快照则不允许从当前主档伪造补建。

### 9.3 快照不可变与报价转订单

快照内容和版本创建后始终不变。草稿中仅调整数量、成交单价、折扣或备注时保留原快照；明确更换 SKU 或刷新商品资料时，重新执行第 9.2 节的获取或创建流程，替换该草稿明细的快照 ID。若当前版本未变，仍复用原有版本的快照。

已确认或已发出的单据不因商品版本递增自动刷新，其业务修订流程仍需保留原快照供历史版本读取。删除主档、草稿明细或单据不级联删除任何共享快照，也不根据单张单据的删除判断快照是否可以清理。

报价转订单时，订单明细直接沿用报价明细的 `product_snapshot_id`，并保留对应报价明细的来源关联；同时承接报价确认的数量、单价和其他交易条件。

这里复用的是不可变快照，不是查询当前 SKU 后重新生成。即使转单前商品名称、规格显示文案、参考售价已经改变，或来源商品已经逻辑删除，仍能按报价中确认的商品资料生成订单。其他履约限制由订单业务单独判断，不影响历史资料读取。

直接新建订单按当前商品版本获取或创建快照；从报价转单则沿用报价已经确认的版本，不自动升级到当前商品版本。订单草稿如明确改选另一 SKU 或刷新商品资料，按第 9.2 节获取或创建对应当前版本快照；仅协商调整成交价格时，修改订单交易字段，商品快照不变。

单据数量按其绑定快照的 `quantity_scale` 校验。SKU 后来调整小数位，不重新校验或舍入历史单据；报价转订单沿用原快照及其精度，明确刷新商品资料时才使用新版本的规则。例如法理纸原快照允许 2 位，已有 1.5 米报价不会因当前 SKU 改为 0 位而被改写。

### 9.4 商品资料与交易信息的边界

| 保存位置 | 保存内容 |
| --- | --- |
| 商品快照 | 商品名称、货号、品牌、型号、类目路径、简要说明、商品与 SKU 两种来源图片及各自主图和顺序、结构化规格、单位及数量精度 |
| 报价 / 订单明细 | `product_snapshot_id`、数量、实际单价、折扣、税率或税额、金额及必要的业务备注 |
| 报价 / 订单自身约定的位置 | 该单据的交易币种 CNY / TWD 和明确的税价口径，随单据冻结，不因 SKU 修改而改写 |
| 当前 SKU | 人工库存、参考采购价及采购币种、参考售价及售价币种，继续作为当前管理数据 |

历史金额使用单据冻结的实际成交字段与交易币种，不重新读取当前参考售价或售价币种。采购币种不决定报价币种；后续报价、订单建议每张单据确定一种交易币种，SKU 参考售价币种不同时需人工确认对应单价，不自动换算，也不直接把不同币种金额相加。快照不保存库存、采购价或采购币种，避免将可变库存和内部管理数据混入客户单据。

### 9.5 图片快照与附件保留

快照图片明细分别保存当时商品与该 SKU 自身的全部附件 ID、来源、主图标记和顺序，不保存会过期的签名 URL。任一来源图片发生变化都递增商品版本，SKU 图片变化还递增 SKU 行版本；旧快照两组图片均保持原样，新版本首次使用时才保存新快照。

例如 V0 商品主图为 A，SKU 图片为空，V0 快照只有 PRODUCT 来源，前端显示 A；V1 给 SKU 添加图片 B，V1 快照含 PRODUCT 来源 A 与 SKU 来源 B，前端显示 B。后来商品主图改为 C，V0 的历史展示仍使用快照里的 A，不能回退查询当前 C；后端始终不将 A 写成 SKU 图片。

被快照引用的全部附件记录和实际存储对象都必须保留，包括非主图。附件删除、孤立文件清理需要检查统一 `product_image` 中商品及 SKU 两种类型的有效引用，以及全部 `product_snapshot_image` 来源引用，不能只检查商品主图。不可通过“保留附件 ID、删除实际文件”宣称图片快照仍可用；历史图片读取也要校验关联单据的权限。

### 9.6 示例与库存边界

1. 商品当前为 V0，SKU `G001-GRAY` 对应“两门金属衣柜 / 灰色 / 宽900mm”。报价 A 使用时查不到 `(SKU, V0)`，生成 S1，S1 的版本为 0，报价 A 关联 S1，成交单价为 500。
2. 商品未更新，报价 B 再次使用该 SKU，直接复用 S1；即使 B 的成交单价是 480，也只改变 B 的交易字段，不新增或修改快照。
3. 一次保存同时改名并修改该 SKU 的参考售价，商品版本从 V0 变为 V1，原 S1 不变，此时不立即生成新快照。
4. 报价 C 或直接新建订单使用当前 SKU 时，生成 V1 快照 S2；后续同版本业务继续复用 S2。报价 A、B 仍引用 S1。
5. 报价 A 转订单继续引用 S1，并承接 A 确认的单价 500，不因当前版本为 V1 改用 S2。
6. 来源 SKU 库存为 0 后被逻辑删除，删除操作递增商品版本，既有 S1、S2 不变。报价和订单继续读取各自快照，预览和导出均不丢失商品信息。

选品中的库存仅是查询时参考值；快照生成、报价保存、报价转订单和订单保存均不改变或预占库存。未来若需要自动库存业务，应单独设计变动与并发规则，不把当前人工数量设置接口直接当作自动扣减接口。

## 11. 第一版验收标准

1. 可以独立建立装潢材料、金属衣柜等类目及下级类目，官网类目与内容不受影响。
2. 可以一次创建商品、结构化规格和多个 SKU；只有单规格的商品也有明确 SKU。
3. 可以按颜色候选值、数值尺寸及类目筛选 SKU，不解析规格展示字符串完成筛选。
4. 重复货号、重复规格组合、维度缺失、跨商品引用、错误值类型均被拒绝，失败时没有部分写入。
5. SKU 库存默认 0，可人工设置为合法的较大、较小或零值；负数及超出该 SKU 配置小数位的数量被拒绝。
6. 同一旧版本并发修改库存时，只允许一个请求成功；普通资料编辑不覆盖当前库存。
7. 查询可以展示每个 SKU 的库存和单位；不出现仓库、入库、出库、预占、自动扣减等业务要求。
8. 商品停用或 SKU 停用后不出现在新增业务选品结果中，管理端保留可查询资料。
9. 数量不为 0 的 SKU 不能直接删除；类目、单位和规格资料按引用规则限制删除。
10. 全部接口使用明确类型与统一返回结构，分页参数统一，图片复用现有附件服务。
11. 类目、商品、SKU、规格和单位只维护一套业务内容，接口没有业务语言参数，不增加业务翻译表；系统提示和错误信息须支持英文、简体中文、繁体中文，资源编码与占位参数保持完整一致。
12. 报价、订单明细关联非空商品快照 ID，完整历史展示只依赖快照及其规格明细，不要求来源商品、SKU、类目或单位仍存在。
13. 修改商品名称、类目、规格显示文案、单位名称或参考价格后，已有快照及历史单据内容保持不变；零库存来源 SKU 逻辑删除后，历史详情、打印、导出仍完整。
14. 报价转订单沿用报价快照和已确认交易信息，不重新取当前主档覆盖；明确更换 SKU 或刷新商品时按当前商品版本获取或创建快照，不修改旧快照。
15. 单据与快照创建失败时整体回滚；快照及图片、规格明细没有修改、删除或主档级联删除入口，历史全部图片对象保留，读取权限随关联单据校验。
16. 商品、规格、SKU 资料、价格、库存及启停或删除每次成功更新，都在同一事务内递增所属商品版本；一次批量保存同一商品只加 1，失败不递增，查询和快照使用不递增。
17. 类目祖先改名、单位名称等共享展示资料改变时，全部受影响商品版本同步递增，未受影响商品不变；类目维护按无并发场景验证版本联动。
18. 同一 SKU、同一商品版本跨单据和重复使用返回同一个快照 ID，不同 SKU 或不同版本不混用；数据库唯一索引阻止并发重复生成。
19. 商品更新后只产生新商品版本，第一次使用时才生成对应版本快照；更新前的快照和单据不变，未曾生成的历史版本不从当前数据补造。
20. 商品支持多图及排序，同一附件不重复绑定；非空列表恰好一张主图，未指定或移除主图时使用目标列表第一张，清空列表后无主图。
21. 图片新增、移除、替换、排序或切换主图成功后，商品版本递增一次；并发图片编辑通过商品版本校验，旧请求不能覆盖新列表，普通资料编辑不覆盖图片。
22. 同版本复用同一份完整图片快照；当前图片列表改变或清空后，旧单据的图片、主图和顺序不变，移除的旧图片仍能通过快照访问。
23. 采购价与售价分别保存币种，只接受 CNY、TWD；支持采购 CNY / 售价 TWD、采购 TWD / 售价 CNY 或两者同币种，金额和币种成对填写、成对清除。
24. 不默认补币种，不接受只有金额或只有币种的半组数据，金额为 0 仍须有币种；显示、交易确认与历史单据始终保留对应币种，不自动换算。
25. SKU 可设置多张自身图片，允许不填或清空。SKU 查询和选品在无图时返回 `images: []`，不存在后端回填商品主图、复制商品图片或新增默认图片字段的行为。
26. 前端有 SKU 图片时显示自身图片，没有时显示商品的一张主图；商品也无主图则显示占位。历史页面只使用同一快照内的来源图片判断，不回查当前主图。
27. 商品图和 SKU 图可使用同一附件，快照仍按来源分别保存并允许各有一张主图；图片和币种变更递增版本，旧快照图片与单据成交币种保持不变。
28. 商品与 SKU 图片只使用 `product_image`。PRODUCT 记录的 `owner_id` 为商品 ID，SKU 记录的 `owner_id` 为 SKU ID，数字 ID 相同时按类型区分。
29. 商品图片查询和整列表替换只处理 PRODUCT 类型，SKU 图片只处理对应 SKU 类型记录；保存、清空或删除任一归属不影响其他归属，共用图片实体和 VO。
30. 吊衣杆和法理纸可以引用同一米单位，分别设置 0 位、2 位小数；1.5 米在吊衣杆上被拒绝，在法理纸上允许，单位表中不因精度不同出现重复的米单位。
31. 小数位调整需检查现存库存，例如库存为 1.5 时不能直接改为 0 位；成功调整同时递增 SKU 及商品版本，不修改其他 SKU 或旧快照，历史单据继续使用当时的精度。
32. 多规格商品至少勾选一个组合才能进入填写页。填写页只显示已加入的 SKU，点击行可展开编辑，收起后已填数据及摘要正确。无规格商品直接填写默认 SKU。
33. 调整弹窗回显当前勾选。确认后填写页同步增删行，取消弹窗保留原选择。返回上一步再继续时保留仍有效的组合和已录数据，同一草稿内重新勾选已移除的组合可恢复已录数据，移除全部时无法保存。
34. 宽度 100、高度 600 对应的 10 种颜色中若只加入 4 种，填写 `SKU-B` 时按生成顺序得到 `SKU-B-01` 至 `SKU-B-04`，反序选择两个维度得到相同的分配。所有条件留空时预览显示全部已添加 SKU 的数量。批量应用只覆盖命中行的指定字段，交叉组以后一次确认的指定值为准，应用前后的已加入组合一致。
35. 取消预览、无匹配，或发现重复编码、超长编号、库存精度、金额币种错误时，草稿保持原样。检测范围包含已加入但未命中本次分组的 SKU。保存商品时，现有接口一次接收当前已加入的 SKU 及其 `selections`，并继续校验全局编码唯一性。
36. 商品管理业务页面通过第 8.2 节的 V8 对照验收。背景面使用现有主题，控件尺寸、间距、对齐、视觉层级和交互状态以原型为准。

## 12. 设计建议与实施边界

本次已确认采购价、售价分别配置人民币 CNY 或新台币 TWD，SKU 可选多图且空图时由前端显示商品主图，后端不额外组装默认图片。商品业务资料不做多语言、系统提示保留国际化、结构化规格、商品多图、SKU 人工库存、商品版本递增与快照按版本复用继续保留。价格币种已经明确，参考价格税价口径仍需在报价设计中确认。

完整 SQL 包含 8 张主档表和 3 张快照表，共 11 张。商品及 SKU 图片统一存入 `product_image`，每条图片记录按类型保存一个归属 ID。

单位、SKU 和快照的建表定义与后端实现已同步。SKU 新增、编辑、库存校验、详情、选品和快照均使用 SKU 自身的数量小数位。
